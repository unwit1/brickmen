# Parametric CAD and Connector Automation

Research status: architecture pass, 2026-09-27.

## Goal

Make functional compatibility **deterministic and replaceable**, even when the visual shell was sculpted by a human, generated by AI, derived from a scan, or imported from another mesh.

The system must never trust an arbitrary mesh's connector.

The manufacturing architecture is:

```
visual intent
 -> visual shell
 -> canonical scale/coordinate system
 -> remove/untrust imported connector geometry
 -> insert validated parametric connector
 -> apply keep-out/articulation rules
 -> DFM analysis
 -> process-specific compensation
 -> manufacturing build artifact
```

## Canonical source split

Every custom component has two conceptual layers.

### 1. Visual shell

Examples:
- sword blade;
- helmet exterior;
- hair silhouette;
- shoulder armor;
- backpack;
- creature appendage.

May come from:
- CadQuery;
- Blender;
- sculpting software;
- AI-assisted mesh generation;
- scan/remesh;
- manually modeled CAD.

### 2. Functional interface

Examples:
- hand-held bar;
- headwear socket;
- neck opening;
- clip;
- back stud/peg;
- articulation pivot.

Must come from:
**Brickmen validated parametric connector library.**

This prevents visual-generation improvements from silently changing fit.

## Recommended canonical files

For parametric hard-surface geometry:

- source: Python/CadQuery;
- neutral geometry: STEP;
- manufacturing mesh/build exchange: 3MF;
- compatibility/display: STL/OBJ only when required;
- hashes for every export.

For organic shells:
- canonical editable Blender/native mesh;
- normalized watertight manufacturing shell;
- parametric connector booleaned into the shell;
- final STEP where a B-rep conversion is practical, otherwise 3MF/mesh.

Do not make STL the canonical source. It has no robust parametric semantics and weak unit/metadata behavior.

## Why CadQuery

CadQuery is a Python parametric CAD system built on OpenCascade.

Current documentation supports export to:
- STEP;
- STL;
- 3MF;
- AMF;
- glTF;
- other formats.

Its Python source is the true parametric representation.

This makes it particularly suitable for:
- connectors;
- calibration coupons;
- gauges;
- jigs;
- mold inserts;
- simple weapons/props;
- dimensional transformations driven by measured profiles.

## Why 3MF

The 3MF Core + Production extensions support much richer manufacturing exchange than naked STL.

Current 3MF Consortium specs include:
- Core;
- Materials/Properties;
- Production;
- Secure Content;
- Boolean Operations;
- Beam Lattice;
- Toolpath (released September 17, 2026);
- emerging volumetric support.

The Production Extension is especially useful because it supports unique identification of parts/resources within a build.

Brickmen should use 3MF metadata where downstream tools preserve it, while also keeping a separate canonical job manifest because slicers may discard unsupported metadata.

## Coordinate system

Define one Brickmen minifigure coordinate convention.

Example:
- units: mm;
- +Z: up;
- +Y: figure front;
- +X: figure right;
- origin: interface-specific datum.

Every connector profile declares:
- local origin;
- insertion axis;
- mating normal;
- keep-out volume;
- articulation envelope;
- support exclusion surfaces.

Adapters convert imported geometry into this coordinate system.

## Connector definition

A connector is not a hard-coded mesh.

Example conceptual schema:

```yaml
connector_id: handheld_bar
revision: 4
nominal_family: lego_3_18_bar_family
parameters:
  length_mm: 5.4
  cad_diameter_mm: profile()
  root_fillet_mm: profile()
fit_class: removable_friction
keepout:
  radial_mm: ...
  axial_mm: ...
process_profile:
  msla_resin_X:
    compensation_model: ...
  fdm_petg_Y:
    compensation_model: ...
```

Physical compensation should be injected from the selected validated machine/material/build profile.

## Geometry factory

Expose:

```
connector.generate(connector_id, params, process_profile)
coupon.generate(coupon_family, sweep)
fixture.generate(fixture_type, specimen_profile)
part.compose(shell, connector, placement)
part.preflight(part, intended_process)
part.export(part, formats)
```

Each output stores:
- generator git commit;
- input JSON;
- dependency versions;
- connector revision;
- compensation profile revision;
- geometry hashes.

A physical sample is therefore reproducible.

## Compensation models

Avoid a single global scale factor.

Store feature-specific functions:

```
outside_cylinder:
  actual = f(cad_diameter, orientation, build_position)

inside_hole:
  actual = g(cad_diameter, orientation, build_position)

slot:
  actual = h(cad_width, orientation)
```

For early profiles, linear interpolation over measured coupon ladders may be enough.

Later:
- polynomial/spline regression;
- uncertainty intervals;
- build-position terms;
- temperature terms.

Never extrapolate far beyond the measured range without forcing a validation coupon.

## Fit-objective solver

The design should target a physical behavior, not a raw dimension.

Input:

```json
{
  "connector_family": "handheld_bar",
  "fit_class": "removable_friction",
  "machine_material_profile": "...",
  "target_peak_insertion_force_N": [null, null],
  "target_peak_removal_force_N": [null, null],
  "max_stress_damage": "none"
}
```

The system searches tested CAD values and selects the candidate with the best evidence.

Until force limits are empirically established, the target force range remains unknown and the profile cannot be fully production-approved.

## Keep-out and articulation geometry

Every connector should include its functional neighborhood.

For example a neck armor connector includes:
- neck bore;
- head underside clearance;
- shoulder sweep;
- arm rotation envelope;
- torso top clearance;
- decoration/contact surfaces.

Preflight should boolean/intersect the shell against these swept volumes and flag collisions.

This is far more reliable than asking a generative model to "make room for the arms."

## Automated shell integration

### Helmet/hair

1. import/sculpt shell;
2. align to canonical head digital twin;
3. enforce minimum shell thickness;
4. subtract head/connector volume;
5. add validated entry chamfer/socket;
6. check face/torso collision;
7. run support-accessibility analysis;
8. export validation render and manufacturing file.

### Held weapon

1. identify intended grip point(s);
2. generate validated bar;
3. generate root transition/fillet;
4. boolean with decorative weapon shell;
5. check min feature/thin-shaft rules;
6. run hand/arm sweep collision;
7. orient candidate builds;
8. generate coupon if connector profile confidence is insufficient.

### Neck armor

1. generate neck interface;
2. subtract head and articulation keep-outs;
3. add armor shell;
4. evaluate arm range;
5. evaluate torso decoration interference;
6. mark contact faces as support-protected.

## DFM rules

Each process profile supplies rules.

### Resin

- minimum free-standing wall;
- minimum pin;
- minimum hole;
- minimum engraving/emboss;
- maximum unsupported span;
- suction/resin-trap prohibition;
- drainage rule;
- support-contact keepouts;
- thin-weapon orientation rules.

### FDM

- nozzle/layer-specific wall;
- bridge;
- overhang;
- minimum hole;
- seam-sensitive connector zones;
- support/contact zones;
- layer-direction structural warnings.

### Injection molding

- draft;
- undercut detection;
- parting-line feasibility;
- minimum/maximum wall;
- rib/boss rules;
- gate/ejector candidate areas;
- shrink/material profile.

The same part can therefore be revalidated when moving from resin to molding.

## AI-generated geometry contract

AI may:
- generate concept geometry;
- generate ornament;
- propose a shell;
- propose support/orientation;
- classify defects.

AI may not:
- invent final connector geometry and mark it validated;
- silently alter validated interface solids;
- bypass minimum-feature rules;
- promote an unmeasured fit.

Before manufacturing an AI-produced part:
1. normalize/repair;
2. delete/replace functional interfaces;
3. deterministic DFM;
4. exact geometry hash;
5. physical validation if any new critical feature exists.

## Automatic design variants

Because connectors are parametric, Brickmen can safely generate:

- the same sword in multiple grip lengths;
- helmet shells on different validated headwear socket revisions;
- armor thickness variants;
- resin/FDM-specific connector compensation;
- calibration ladders;
- process bridge versions for molded tooling.

All variants retain one visual design lineage.

## Golden geometry tests

Treat geometry generators like software.

Unit/regression tests:
- exported bounding box;
- connector diameter before process compensation;
- exact datum location;
- volume;
- watertightness;
- no forbidden keep-out intersections;
- known mesh hashes when deterministic;
- test boolean against canonical mating digital twin.

For each connector revision include at least one reference fixture and expected measurement manifest.

## Toolchain recommendation

### Deterministic geometry
- CadQuery/OpenCascade.

### Organic/visual shell
- Blender with scripted import/export and modifiers.

### Exchange
- STEP + 3MF.

### 3MF library
- lib3mf when direct metadata/package manipulation is needed.

### Mesh validation
- dedicated deterministic mesh checks;
- slicer preflight;
- UVtools for resin slice-level issues.

### Source control
- store generator source, JSON inputs, schemas and small reference geometry in Git;
- avoid committing huge generated/sliced build artifacts unless needed for reproducibility;
- retain hashes/manifest and archive high-volume outputs locally.

## Initial connector package

Implement in this order:

1. `handheld_bar`
2. `headwear_socket`
3. `neck_armor_opening`
4. `back_attachment`
5. `clip`
6. torso/arm interfaces only after accessory workflow is stable
7. hip/leg/hand articulated interfaces as later R&D.

This sequencing captures most custom accessory value without immediately solving the hardest full-minifigure joint problems.
